CAN 与 CANopen 的关系

CAN（Controller Area Network）是 ISO 11898 定义的串行通信总线，只规定了物理层和数据链路层（报文怎么发、怎么仲裁、怎么检错）。它本身不解释“数据字节代表什么”。

CANopen 是构建在 CAN 之上的应用层协议（CiA 301），它定义了设备如何描述自己（对象字典）、如何交换数据（通信对象）、如何管理网络（NMT）。打个比方：

类比

CAN 像“公路系统”（路面、车道、红绿灯规则）；CANopen 像“交通规则与货物标准”（车辆类型、货物标签、调度命令）。同样的公路上可以跑 CANopen、DeviceNet、J1939 等不同应用层协议。

为什么要学 CANopen

  • 工业自动化主流：PLC、伺服驱动、传感器、IO 模块广泛使用 CANopen。
  • 汽车与特种车辆：商用车、工程机械、农业机械大量采用 CANopen 派生协议。
  • 机器人与医疗：关节驱动、传感网络常基于 CANopen（CiA 402）。
  • 标准化配置：EDS/DCF 文件让设备即插即用，省去大量底层调试。

预备知识

学习本站教程，建议具备：

  • 基本的数字电路与二进制 / 十六进制换算能力。
  • 了解 UART / SPI / I2C 等至少一种串行通信。
  • 基本的 C 语言阅读能力（示例代码用 C 描述）。

第 1 章 · CAN 基础与物理层

理解 CAN 总线是什么、为什么抗干扰强、以及节点如何在同一根线上“文明地”抢着说话。

1.1 什么是 CAN

CAN（Controller Area Network，控制器局域网）是一种多主、串行、异步、差分的现场总线。它由德国 Bosch 公司于 1986 年提出，最初用于汽车内部的 ECU（电子控制单元）互联，如今已广泛应用于工业自动化、工程机械、轨道交通、医疗设备等领域。

  • 1991：Bosch 发布 CAN 2.0 规范（2.0A 标准帧 / 2.0B 扩展帧）。
  • 1993：成为国际标准 ISO 11898（高速 CAN）和 ISO 11519（低速容错 CAN）。
  • 2012：Bosch 发布 CAN FD（Flexible Data-rate），支持更高带宽与更长数据场。

CAN 只定义了物理层和数据链路层（介质访问控制 + 逻辑链路控制），不规定应用层语义。这也是为什么在同一 CAN 总线上可以同时存在 CANopen、DeviceNet、J1939 等不同应用层协议。

1.2 CAN 的核心特点

  • 多主（Multi-master）：任何节点都可在总线空闲时主动发起通信，无中心节点。
  • 广播（Broadcast）：所有节点都能收到每一帧，由报文标识符决定是否处理。
  • 非破坏性仲裁：多节点同时发送时，优先级高的报文完整发出，低优先级的自动退避，不会破坏总线上的任何位。
  • 差分信号：使用 CAN_H / CAN_L 双绞线，抗电磁干扰能力强。
  • 强大的错误检测：位错误、填充错误、CRC 错误、格式错误、应答错误，5 种检错机制。
  • 故障界定：节点能区分临时干扰与永久性故障，故障节点可自动脱离总线（Bus-Off），不影响全网。

1.3 物理层：差分信号

CAN 使用一对双绞线传输差分信号：CAN_H 与 CAN_L。总线上只有两种逻辑状态：

“线与”逻辑

只要有任意一个节点输出显性，总线就是显性；只有所有节点都输出隐性，总线才是隐性。这种“线与”特性是 CAN 仲裁的物理基础。

1.4 终端电阻与拓扑

高速 CAN（ISO 11898-2）必须使用线性总线拓扑，并在总线两端各接一个 120 Ω 终端电阻，用于：

  • 阻抗匹配，抑制信号反射（否则高速时会出现振铃，导致误判）。
  • 在隐性状态下为总线提供约 2.5 V 的偏置电平。
  [节点1]──[节点2]──[节点3]── ... ──[节点N]
     │                          │
   120Ω                       120Ω
     │                          │
   ─────────── CAN 总线（双绞线）───────────
常见错误

不要挂星形、树形拓扑；不要在中间加终端电阻；线缆应使用特性阻抗 120 Ω 的双绞线。错误拓扑会导致通信不稳定甚至完全无法通信。

1.5 波特率与总线长度

CAN 波特率越高，允许的总线越短（受信号传播延迟限制）。常用经验值：

波特率最大总线长度（参考）典型应用
1 Mbps≈ 40 m汽车动力总成、高实时控制
500 kbps≈ 100 m工业自动化最常用
250 kbps≈ 250 m工程机械、较长总线
125 kbps≈ 500 m大楼自动化、长距离
50 kbps≈ 1000 m超长距离、低速

同一总线上所有节点必须使用完全相同的波特率，且位时序参数（SJW、TSEG1、TSEG2）也需匹配，否则会出现错误帧。

1.6 多主与非破坏性仲裁

CAN 采用 CSMA/CD + AMP（载波侦听多路访问 / 冲突检测 + 逐位仲裁）。当多个节点同时检测到总线空闲并开始发送时：

  1. 所有节点从标识符（ID）的最高位开始逐位发送。
  2. 每发完一位，节点都回读总线实际电平。
  3. 若某节点发的是隐性(1)，却读到总线为显性(0)，说明有更高优先级节点在发送 → 该节点立即停止发送（退避），转为接收。
  4. 由于“线与”特性，高优先级报文的每一位都完整、不受破坏地出现在总线上。

因此：标识符数值越小，优先级越高（因为显性=0，越靠前出现 0 越早压制对手）。

示例

节点 A 发 ID = 0b101（5），节点 B 发 ID = 0b100（4），同时发送：

  • 第 1 位：都发 1（隐性）→ 总线 1，都通过。
  • 第 2 位：都发 0（显性）→ 总线 0，都通过。
  • 第 3 位：A 发 1，B 发 0 → 总线被 B 拉成 0。A 读到 0 ≠ 自己发的 1 → A 仲裁失败，退避。
  • 结果：B（ID=4）完整发出，A 等待下一次总线空闲重发。整个过程没有任何数据被破坏。

1.7 四种帧类型

帧类型用途说明
数据帧 Data Frame携带数据最常用，0~8 字节（CAN FD 可达 64 字节）
远程帧 Remote Frame请求数据RTR=1，无数据场，请求某标识符的节点回应数据帧
错误帧 Error Frame报错6 个连续显性位（错误标志）+ 8 个隐性位（错误界定符）
过载帧 Overload Frame请求延迟接收方来不及处理时插入，暂停后续帧发送

1.8 位填充（Bit Stuffing）

为了保证接收方能从信号中恢复时钟（CAN 无独立时钟线，靠边沿同步），规定：

发送方在发送5 个相同极性的位之后，必须插入 1 个相反极性的位；接收方收到后将其去除。

例如发送 000000，实际线上为 00000 1 0（插入的 1 即填充位）。

位填充只作用于帧起始到 CRC 序列（含）；CRC 界定符、ACK、EOF 等固定字段不填充。错误帧也不填充。

1.9 CAN 2.0A / 2.0B 与 CAN FD

  • CAN 2.0A：仅支持 11 位标准标识符（Standard ID）。
  • CAN 2.0B（主动）：同时支持 11 位标准帧和 29 位扩展帧（Extended ID），通过 SRR/IDE 位区分。
  • CAN FD：兼容经典 CAN 帧结构，支持更长数据场（最多 64 字节）和数据段更快波特率，汽车领域逐步普及。
本章小结

CAN = 差分 + 多主 + 非破坏性仲裁 + 强错误检测。显性=0 覆盖隐性=1 是仲裁的物理本质；120 Ω 终端电阻与线性拓扑是稳定通信的前提；所有节点波特率必须一致。下一章我们深入到帧的每一个位域。

第 2 章 · 帧格式、位时序与错误

把一帧 CAN 报文拆到“位”，理解每个字段的含义，以及出错时总线会发生什么。

2.1 标准数据帧（11 位 ID）

标准数据帧由 7 个场组成，下图为完整位域（不含填充位）：

SOFID[10:0]RTRIDEr0DLCDataCRCCRC_dACKACK_dEOFIFS

SOF=帧起始；ID=标识符；DLC=数据长度码；CRC_d=CRC界定符；ACK_d=ACK界定符；EOF=帧结束；IFS=帧间间隔

场位数说明
SOF（帧起始）1单个显性位(0)，标志帧开始，同时用于硬同步
仲裁场12+211 位 ID + RTR + IDE + r0
控制场6r0(保留) + 4 位 DLC + r0
数据场0~640~8 字节，由 DLC 指定长度
CRC 场1615 位 CRC + 1 位 CRC 界定符(隐性)
ACK 场2ACK 槽 + ACK 界定符(隐性)
EOF77 个连续隐性位，标志帧结束
IFS33 个隐性位的帧间间隔

关键字段解释

  • ID（标识符）：既是报文地址，也是仲裁优先级。11 位范围 0x000 ~ 0x7FF。
  • RTR（远程发送请求）：数据帧 = 0（显性），远程帧 = 1（隐性）。
  • IDE（标识符扩展位）：标准帧 = 0，扩展帧 = 1。
  • DLC（数据长度码）：4 位，取值 0~8 表示数据字节数；9~15 也按 8 字节处理。
  • ACK 槽：发送方发隐性，任何正确接收的节点都回写显性，表示“我收到了”。
示例：发送 0x123 携带数据 [0x11, 0x22]

ID = 0x123 = 0b001 0010 0011，DLC = 2。用工具（如 candump）抓到的典型输出：

  can0  123   [2]  11 22

2.2 扩展数据帧（29 位 ID）

扩展帧（CAN 2.0B）将标识符扩展到 29 位，仲裁场多了一个 SRR 位和 IDE：

SOFID28-18SRRIDEID17-0RTRr1r0DLCDataCRC...
  • SRR（替代远程请求）：固定为隐性(1)，占据标准帧 RTR 的位置，确保相同基础 ID 时标准帧优先级高于扩展帧。
  • IDE = 1：表示此为扩展帧。
  • 29 位 ID 范围 0x00000000 ~ 0x1FFFFFFF。

2.3 远程帧

远程帧用于请求其他节点发送指定标识符的数据帧：

  • RTR = 1（隐性）。
  • 没有数据场（DLC 仍按期望长度设置，但不发送数据）。
  • 当某节点收到“自己负责的 ID”的远程帧时，应以对应 ID 发回数据帧。

在 CANopen 等现代应用层中，远程帧很少使用（SDO/PDO 已覆盖请求/响应场景），但经典 CAN 应用中仍可见到。

2.4 位时序与采样点

CAN 没有独立时钟线，接收方靠信号边沿同步。每一位时间（Bit Time）被划分为若干时间份额（TQ）：

SSPTSPS1采样点PS2
段含义典型 TQ 数
SS 同步段边沿对齐，固定 1 TQ1
PTS 传播段补偿信号在总线与收发器的延迟1~8
PS1 相位段 1可被 SJW 延长1~8
PS2 相位段 2可被 SJW 缩短1~8
  • 采样点（Sample Point） = (SS + PTS + PS1) / 总TQ，通常设在 75%~87.5% 处。
  • SJW（同步跳转宽度）：每次重同步允许调整的最大 TQ 数，一般设 1~2 TQ。
  • 总 TQ 数 = SS + PTS + PS1 + PS2，通常取 8~25。
例：500 kbps，8 MHz 时钟，采样点 87.5%

若预分频使 1 TQ = 125 ns，则 1 位 = 16 TQ = 2 μs → 500 kbps。配置：SS=1, PTS=2, PS1=11, PS2=2 → 采样点 = (1+2+11)/16 = 87.5%。

SJA1000 类寄存器常见写法：BTR0 = 0x00（SJW=1, 波特率预分频），BTR1 = 0x1C（采样点配置）。不同芯片换算不同，务必查手册。

2.5 五种错误检测

错误类型检测者触发条件
位错误 Bit Error发送节点发送的位与回读到的总线电平不符（仲裁场/ACK 槽除外）
填充错误 Stuff Error所有节点检测到 6 个连续相同极性的位
CRC 错误接收节点收到的 CRC 与本地计算不一致
格式错误 Form Error所有节点固定格式位（EOF/界定符等）出现非法显性位
应答错误 ACK Error发送节点ACK 槽未读到显性（无人确认）

2.6 错误状态机（TEC / REC）

每个节点维护两个计数器：TEC（发送错误计数）和 REC（接收错误计数），根据错误事件加减：

  • Error Active（错误主动）：TEC ≤ 127 且 REC ≤ 127。节点发现错误时发送6 个显性位的主动错误标志，强力打断当前帧。
  • Error Passive（错误被动）：TEC 或 REC ≥ 128 且 ≤ 255。节点只能发6 个隐性位的被动错误标志，且发送成功后需等待 8 个额外隐性位（暂停发送）。
  • Bus-Off（总线关闭）：TEC ≥ 256。节点完全脱离总线，不再影响总线。恢复需软件触发或在 128×11 个隐性位后自动恢复（具体看芯片配置）。
频繁进 Bus-Off 排查思路
  1. 两端 120 Ω 终端电阻是否装好？用万用表测 CAN_H/CAN_L 间应为 60 Ω 左右。
  2. 波特率 / 位时序是否全网一致？
  3. 线缆是否过长或拓扑错误？
  4. 收发器供电/地是否正常？有无强干扰源（变频器、电机）？
  5. 用示波器看波形是否有振铃、台阶。

2.7 错误帧结构

错误标志错误界定符
  • 错误标志：主动错误 = 6 个显性；被动错误 = 6 个隐性（可能被其他节点的显性覆盖）。
  • 错误界定符：8 个隐性位，之后节点重新尝试发送或恢复。

当多个节点同时报错时，错误标志会叠加成最多 6~12 个显性位，但不会破坏后续数据——出错的帧会被整帧丢弃并重发，保证数据完整性。

本章小结

一帧 CAN 报文从 SOF 到 IFS，每个位域各司其职；采样点设在 75%~87.5% 最稳妥；5 种错误检测 + TEC/REC 状态机让 CAN 在干扰下仍能自愈。下一章进入应用层，看看 CANopen 如何组织这些原始帧。

第 3 章 · CANopen 概述

CANopen = CAN 之上的应用层。本章建立整体心智模型：设备由什么组成、节点之间怎么说话、上电后经历哪些状态。

3.1 什么是 CANopen

CANopen 是由 CiA（CAN in Automation）组织制定的、基于 CAN 总线的应用层协议，核心规范是 CiA 301。它在原始 CAN 帧之上定义了：

  • 设备如何描述自身（对象字典 Object Dictionary）。
  • 设备之间如何交换数据（通信对象 Communication Objects）。
  • 网络如何被管理与监控（NMT、心跳、EMCY）。
  • 设备如何被标准化配置（EDS/DCF 文件、设备子协议 CiA 4xx）。

一句话：CANopen 把“裸 CAN 报文”变成了“有语义、可配置、即插即用的设备通信”。

相关规范
  • CiA 301：应用层与通信规范（核心）。
  • CiA 302：网络管理与规划。
  • CiA 305：LSS 层设置服务（动态分配 Node-ID / 波特率）。
  • CiA 306：电子数据表（EDS / DCF）格式。
  • CiA 401：IO 模块设备子协议。
  • CiA 402：驱动器与运动控制设备子协议。

3.2 CANopen 设备模型

每个 CANopen 设备由三部分组成：

通信单元

实现 CAN 收发与各类通信对象（SDO/PDO/NMT 等）。

对象字典 OD

设备的“通讯录+配置表”，所有参数与数据都映射为 OD 条目。

应用 / 功能单元

设备的实际功能（如 ADC、PWM、电机控制），由设备子协议定义。

对象字典（OD）是 CANopen 的灵魂。外部对设备的所有读写，本质上都是在读写对象字典中的某一条目。下一章专门讲解。

3.6 节点状态机（NMT State Machine）

每个 CANopen 节点有 4 个状态：

Initialization→Pre-operational↔Operational↔Stopped
  • Initialization（初始化）：上电后短暂状态，加载参数、初始化 OD，完成后自动进入 Pre-operational 并发 Boot-up 报文（0x700+ID，数据=0x00）。
  • Pre-operational（预操作）：可进行 SDO 配置、心跳、EMCY、SYNC 接收，但 PDO 不传输。用于启动时配置参数。
  • Operational（操作）：正常工作，PDO 开始传输。
  • Stopped（停止）：仅维持 NMT 与心跳，不发 PDO 也不响应 SDO。

NMT 控制命令

主站发 0x000，数据场 2 字节：[命令码, 目标Node-ID]（Node-ID=0 表示广播给所有节点）。

命令码含义
0x01进入 Operational（启动）
0x02进入 Stopped
0x80进入 Pre-operational
0x81复位节点（Reset Node）→ Initialization
0x82复位通信（Reset Communication）→ Initialization

3.7 典型启动流程

1. 节点上电 → Initialization → 初始化对象字典
2. 自动进入 Pre-operational
   → 发送 Boot-up:  ID=0x700+NodeID  Data=[0x00]
3. 主站收到 Boot-up，开始用 SDO (0x600+ID) 配置节点参数
   (映射 PDO、设置心跳时间等)
4. 主站发送 NMT Start:  ID=0x000  Data=[0x01, NodeID]
5. 节点进入 Operational，开始周期性 PDO 通信
6. 主站持续监听心跳 (0x700+ID) 与 EMCY (0x080+ID) 监控状态
本章小结

CANopen 用对象字典统一设备描述，用预定义 COB-ID 实现上电即用，用 NMT 状态机管理生命周期。记住 0x600+ID / 0x580+ID 是 SDO，0x180+ID / 0x200+ID 是 PDO1，0x700+ID 是心跳——这是抓包分析的起点。下一章深入对象字典。

第 4 章 · 对象字典（OD）

对象字典是 CANopen 的灵魂。所有参数、数据、配置都在这里——读懂它，就读懂了一台设备。

4.1 什么是对象字典

对象字典（Object Dictionary, OD）是一个有序的参数集合，描述了设备的全部数据与功能。它是外部与设备交互的唯一入口：

SDO 读写的是 OD 条目；PDO 传输的是 OD 条目的值；NMT 操作的也是 OD 中定义的状态。

每个对象用一个 16 位索引（Index）定位，复杂对象再用一个 8 位 子索引（Sub-index）细分。访问格式常写作：0x索引:子索引，例如 0x1018:01。

4.2 对象的结构

每个对象字典条目包含以下属性：

属性含义
Index16 位索引，对象的地址
Sub-index8 位子索引，0 号常表示元素数量/最大子索引
Name对象名称
Type数据类型（如 UNSIGNED32、VISIBLE_STRING）
Attr访问属性：ro / wo / rw / const，是否可映射到 PDO
Default默认值
PDO Mapping是否允许映射到 PDO（mpo = mappable）

4.3 索引分区

16 位索引空间按用途划分为若干区域：

索引范围区域用途
0x0000保留不使用
0x0001 – 0x0FFF数据类型区静态数据类型定义（基本类型、数组、记录）
0x1000 – 0x1FFF通信行规区CANopen 通信参数（所有设备都有）
0x2000 – 0x5FFF制造商特定区厂商自定义参数（无统一规范）
0x6000 – 0x9FFF标准设备行规区由设备子协议定义（如 CiA 402 驱动对象）
0xA000 – 0xFFFF保留 / 未来—

0x1018:03 = 0x00010002   (Revision Number 版本号)
0x1018:04 = 0x0000ABCD   (Serial Number 序列号)

第 5 章 · 通信对象（SDO / PDO / NMT）

CANopen 的数据如何流动？本章逐个拆解 SDO、PDO、NMT、SYNC、EMCY、心跳的报文格式与使用场景。

5.1 SDO —— 服务数据对象

SDO（Service Data Object）用于读写对象字典，采用客户端-服务器模型，请求-响应式，可靠但开销大，适合配置参数与偶发数据交换。

一对 SDO 通道用 2 个 CAN ID：

  • SDO 服务器接收（客户端 → 服务器）：0x600 + Node-ID
  • SDO 服务器发送（服务器 → 客户端）：0x580 + Node-ID

每帧数据场固定 8 字节：[命令码, 索引低, 索引高, 子索引, 数据0..3]。

5.1.1 SDO 命令码（首字节）

命令码方向含义
0x40客户端→服务器SDO 读请求（Initiate Upload Request）
0x20客户端→服务器SDO 写请求（普通，非加速）
0x2F客户端→服务器SDO 写请求（加速，1 字节数据）
0x2B客户端→服务器SDO 写请求（加速，2 字节数据）
0x23客户端→服务器SDO 写请求（加速，4 字节数据）
0x43服务器→客户端SDO 读响应（加速，4 字节）
0x4B服务器→客户端SDO 读响应（加速，2 字节）
0x4F服务器→客户端SDO 读响应（加速，1 字节）
0x42服务器→客户端SDO 读响应（普通，需分段上传）
0x60服务器→客户端SDO 写响应（下载确认）
0x80服务器→客户端SDO 错误响应（后跟 4 字节错误码）
例 1：读取 Node-ID=1 的心跳周期（0x1017:00，UINT16）
请求  ID=0x601  [40 17 10 00 00 00 00 00]   ← 0x40 读, 索引0x1017, 子索引0x00
响应  ID=0x581  [4B 17 10 00 E8 03 00 00]   ← 0x4B 2字节, 值=0x03E8=1000ms
例 2：写 Node-ID=1 的心跳周期为 500ms（0x01F4）
请求  ID=0x601  [2B 17 10 00 F4 01 00 00]   ← 0x2B 写2字节, 0x01F4 小端
响应  ID=0x581  [60 17 10 00 00 00 00 00]   ← 0x60 写成功

5.1.2 加速传输 vs 分段传输

  • 加速传输（Expedited）：数据 ≤ 4 字节时，单帧完成读写，命令码带 0x23/0x2B/0x2F（写）或 0x43/0x4B/0x4F（读）。
  • 分段传输（Segmented）：数据 > 4 字节（如字符串、DOMAIN 固件），先发 0x20/0x42 声明长度，再用 0x00/0x01 段命令逐帧传输，每帧最多 7 字节数据，带翻转位与最后段标志。
  • 块传输（Block）：CiA 301 补充，适合大数据（固件升级），一次连续发多个段再统一确认，效率更高。

5.2 PDO —— 过程数据对象

PDO（Process Data Object）用于传输实时过程数据，采用生产者-消费者模型，广播，无确认、开销小、带宽高。分两类：

  • TPDO：本节点生产（发送）的数据。
  • RPDO：本节点消费（接收）的数据。

每个节点默认最多支持 4 个 TPDO + 4 个 RPDO（可扩展到 512 个）。

5.2.1 PDO 映射（Mapping）

PDO 不直接对应某个 OD 对象，而是通过映射参数把若干 OD 条目打包进一帧 8 字节：

  • TPDO 映射：0x1A00 + n（n=0..3 对应 TPDO1~4）
  • RPDO 映射：0x1600 + n

每个映射条目是一个 32 位值：索引(16位) | 子索引(8位) | 位长度(8位)。子索引 0 表示映射条目数量。

例：TPDO1 映射“状态字 + 实际位置”
0x1A00:00 = 2            (2 个映射对象)
0x1A00:01 = 0x40410010   (0x6041:00 状态字, 16位)   ← 索引0x6041,子索引0,长度0x10
0x1A00:02 = 0x40640020   (0x6064:00 实际位置, 32位) ← 长度0x20
# 一帧 TPDO1 共 48 位 = 6 字节，CAN 数据场为 [状态字低, 状态字高, 位置0,1,2,3]

注意：映射修改前必须先禁用该 PDO（把 0x1800 子索引 1 的 COB-ID 最高位置 1），改完再启用。

5.2.2 PDO 通信参数

每个 PDO 的通信参数在 0x1800+n（TPDO）/ 0x1400+n（RPDO）：

子索引名称说明
0x01COB-ID该 PDO 的 CAN ID，最高位=1 表示禁用
0x02传输类型见下表
0x03禁止时间 Inhibit TimeTPDO 最小发送间隔（100μs 单位），防止刷屏
0x05事件定时器 Event Timer异步 TPDO 的周期（ms），到点强制发送
0x06SYNC 起始值同步 PDO 从第几个 SYNC 计数器开始

5.2.3 传输类型

值类型触发方式
0x00同步 acyclic收到 SYNC 后，仅当数据变化时发送
0x01 – 0xF0同步 cyclic每 N 个 SYNC 周期发送一次
0xFC同步 RTR由远程帧 + SYNC 触发
0xFD异步 RTR由远程帧触发

选型建议

配置参数 → 用 SDO；周期性实时数据（位置、速度、IO 状态）→ 用 PDO。PDO 映射尽量固定在 8 字节内，避免频繁重映射。

5.4 SYNC —— 同步对象

SYNC 由主站周期性发送（默认 ID 0x080），为全网提供统一时钟，触发同步型 PDO 的采样与发送。

  • 相关对象：0x1005（COB-ID SYNC）、0x1006（周期 μs）、0x1019（SYNC 计数器溢出值）。
  • SYNC 帧通常无数据（0 字节）；若启用计数器，数据场为 1 字节计数（1..240 循环）。
  • 同步型 PDO 节点在收到 SYNC 后立即采样输入、输出，保证多轴运动同步。

5.6 心跳（Heartbeat）与节点守护（Node Guarding）

两者都用于监控节点存活，二选一（优先用心跳）。

心跳 Heartbeat

  • 被监控节点（生产者）周期发送 ID 0x700 + Node-ID，1 字节数据 = 当前状态：
状态值状态
0x00Boot-up（启动报文，仅发一次）
0x04Stopped
0x05Operational
0x7FPre-operational
  • 生产者周期由 0x1017（Producer Heartbeat Time，ms）设置。
  • 消费者（监控方）在 0x1016（Consumer Heartbeat Time）配置：每个被监控节点的 Node-ID 和超时时间，超时未收到即判定节点掉线。

节点守护 Node Guarding

  • 主站向 0x700 + Node-ID 发远程帧（RTR），从站响应同 ID，数据 = 状态 + toggle bit（翻转位）。
  • 周期由 0x100C（Guard Time，ms）× 0x100D（Life Time Factor）= 超时时间。
  • 若连续两次响应 toggle 未翻转，或超时无响应 → 判定故障。
